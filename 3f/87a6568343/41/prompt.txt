# Architectural Refactoring: Separate Formal Layer from Data Layer

## Context

The user identified a critical architectural issue in spec-core: **SpecGraph (data layer) performs formal verification, which should be UDAFModel's (formal layer) responsibility.**

### Current Problems

1. **SpecGraph (graph.rs, 2792 lines)** mixes responsibilities:
   - Data persistence (nodes, edges, serialization) ✓ Correct
   - **Formal verification** (detect_contradiction_via_z3, Prover usage) ✗ Wrong layer
   - Imports `formal::{AdmissibleSet, Constraint, Prover}` - layer violation

2. **UDAFModel has incomplete verification**:
   - Line 252: `// TODO: Implement SMT-based satisfiability check`
   - `detect_contradictions()` is a stub (only checks marked contradictions)
   - Prover exists but not integrated into UDAFModel

3. **Duplicate logic**:
   - `SpecGraph::extract_constraints_from_content()` (lines 900-1018)
   - `UDAFModel::extract_constraints_from_text()` (model.rs lines 280-461)
   - Nearly identical implementations

4. **Confusing naming**:
   - "SpecGraph" sounds like specification logic, but should be data-only
   - Layer boundaries unclear

### User Requirements

- **SpecGraph should be purely for persisting UAD/f model data** (graph representation)
- **Formal verification should be in formal/ layer only**
- **Consider renaming** to clarify purpose
- **Separate "formal world" from "data world"**

### Theoretical Foundation

Per UAD/f theory (docs/conversation.md):
- **U/D/A/f model**: Universe, Domain, Admissible Set, Transform Functions
- **Formal verification**: Proving ∃x. (x ∈ A₁ ∧ x ∈ A₂), checking A₁ ∩ A₂ = ∅
- **SpecGraph should be**: Data representation for persistence
- **UDAFModel should be**: Verification authority for formal proofs

### Step 3: Implement Formal Verification Layer (UDAFModel)

**formal/model/verify.rs** (NEW FILE):
```rust
impl UDAFModel {
    pub fn detect_contradictions(&self) -> Vec<ContradictionProof> {
        let mut results = Vec::new();
        let spec_ids: Vec<_> = self.admissible_sets.keys().collect();

        for i in 0..spec_ids.len() {
            for j in (i+1)..spec_ids.len() {
                let proof = self.prover.prove_consistency(
                    &self.admissible_sets[spec_ids[i]],
                    &self.admissible_sets[spec_ids[j]]
                );

                if proof.status == ProofStatus::Refuted {
                    results.push(ContradictionProof {
                        spec_a: spec_ids[i].clone(),
                        spec_b: spec_ids[j].clone(),
                        proof,
                    });
                }
            }
        }

        results
    }

    pub fn detect_omissions(&self) -> Vec<OmissionReport> {
        // Detect underspecified regions using Prover
        self.prover.detect_underspecification(self)
    }
}
```
