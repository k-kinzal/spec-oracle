# Refactoring Plan: Reorganize spec-core into formal/ Directory

## Context

The user requested to refactor spec-core by:
1. Moving all code into `spec-core/src/formal/` (formal verification layer)
2. Splitting large files (udaf.rs: 1,536 LOC, prover/mod.rs: 1,238 LOC) into smaller modules
3. Following Rust best practices with clear directory structure
4. **Key insight**: `formal/` IS the UDA/f space itself, not a wrapper around `udaf/`
5. **Important**: Each concept (U/D/A/f) should have its own directory with ID types included

### Current Problems

- udaf.rs (1,536 LOC) - too large, mixes all UDA/f concepts
- prover/mod.rs (1,238 LOC) - too large, mixes proof types and implementation
- IDs are separated in udaf/ids.rs instead of living with their models
- Metadata scattered across files
- No clear conceptual organization

---

## Target Directory Structure

Each UDA/f concept gets its own directory. ID types live with their models.

```
formal/
  mod.rs                        # Entry point, re-exports

  universe/                     # U (Universe)
    mod.rs
    universe.rs                 # Universe type
    universe_id.rs              # UniverseId
    universe_metadata.rs        # UniverseMetadata

  domain/                       # D (Domain)
    mod.rs
    domain.rs                   # Domain + DomainProofData
    domain_id.rs                # DomainId
    domain_metadata.rs          # DomainMetadata
    domain_set.rs               # DomainSet reference collection

  admissible_set/               # A (Admissible Set)
    mod.rs
    admissible_set.rs           # AdmissibleSet + ProofData
    spec_id.rs                  # SpecId
    spec_set.rs                 # SpecSet reference collection
    admissible_set_metadata.rs  # Metadata

  constraint/
    mod.rs
    constraint.rs               # Constraint + ConstraintKind
    constraint_metadata.rs      # ConstraintMetadata

  transform/                    # f (Transform Functions)
    mod.rs
    transform.rs                # TransformFunction + Kind + Strategy
    transform_id.rs             # TransformId
    transform_metadata.rs       # TransformMetadata

  model/                        # UDAFModel orchestrator
    mod.rs
    model.rs                    # Core UDAFModel struct + methods
    populate.rs                 # populate_from_graph logic
    serde_helpers.rs            # Serialization helpers

  metadata/                     # Shared metadata infrastructure
    mod.rs
    metadata_key.rs             # MetadataKey enum
    metadata.rs                 # Base Metadata type

  proof/                        # Proof mechanisms
    mod.rs
    types.rs                    # Proof, Property, ProofStatus, etc.
    prover.rs                   # Prover implementation
    underspec.rs                # Underspecification detection
    z3_backend.rs               # Z3 integration
```
