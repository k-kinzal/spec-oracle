# UAD/f モデル型厳密化プラン

## Context

UAD/f モデル (`spec-core/src/udaf.rs`) の実装が型安全性に欠けており、以下の問題が発生しています：

1. **String ID の多用**: Universe.id, Domain.id などすべて String で、命名規則が強制されていない
2. **HashMap<String, String> metadata**: キーも値も自由形式で、タイプミスが検出されない
3. **参照の整合性なし**: HashSet<String> で ID 参照しているが、参照先の存在確認がない
4. **設計上の矛盾**: Universe に layer フィールドが存在するが、Universe 自体が層を表すため冗長

これらを解決するため、型システムを活用した厳密化を行います。

## 修正方針

### 1. ID 型システムの導入

newtype パターンで専用の ID 型を定義：

- **UniverseId**: "U0", "U1" などの形式を強制、parse 時にバリデーション
- **DomainId**: UUID ベース
- **SpecId**: UUID ベース
- **TransformId**: "f_SOURCE_to_TARGET" 形式を強制

各 ID 型は：
- `parse()` でバリデーション
- `as_str()` で String への変換
- Serialize/Deserialize 対応

### 2. Metadata 型システムの導入

**MetadataKey enum** で既知のキーを列挙：
- Universe, SourceFile, RpcName, Extractor, Inferred, Variable, ImplCode, TestCode, Pattern, Value, Min, Max, Source
- Custom(String) で拡張可能性を保持

**専用 Metadata 型**：
- UniverseMetadata, DomainMetadata, ConstraintMetadata, TransformMetadata
- 各型で頻繁に使われるキーにアクセサメソッド提供
- 内部的には HashMap<String, String> を保持（互換性）

### 3. 型安全な参照集合

**SpecSet**, **DomainSet** で型安全な ID 集合管理：
- `insert(id: SpecId)`, `contains(&SpecId)` で型チェック
- `validate(&HashSet<SpecId>)` で参照整合性検証
- 内部は HashSet<String> で serialize 互換性維持

### 4. Universe.layer フィールドの削除

Universe 自体が層を表すため、layer フィールドは冗長。削除して id から導出：

```rust
impl Universe {
    pub fn layer(&self) -> u8 {
        self.id.layer()  // UniverseId から抽出
    }
}
```

### 5. 参照整合性検証

`UDAFModel::validate()` メソッドで全参照をチェック：
- Universe の specifications が存在する SpecId を指しているか
- Domain の universe_id が存在する UniverseId を指しているか
- Transform の source_universe, target_universe が存在するか

### Phase 4: 内部実装の更新

**spec-core/src/udaf.rs**:

`populate_from_graph()`:
- ノードの metadata から universe を取得する際、MetadataKey::Universe 使用

`construct_u0()`:
- `format!("f_{}_to_U0", universe_id)` → `TransformId::inverse(&universe_id)`

`detect_contradictions()`:
- `admissible_sets.keys()` が SpecId のイテレータに

`extract_constraints_from_text()`:
- metadata 挿入を MetadataKey 使用
