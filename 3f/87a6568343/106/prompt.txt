# UAD/f Two-Operator Kernel under Partial Projections: A Lean4 Mechanization

## Abstract
We present a mechanized formal kernel for multi-layer specification comparison under partial projections (`Option`).
The kernel separates two operators on the same typed model: `U0` (join-side root coverage baseline) and `UAnd` (meet-side conjunctive consistency).
Our contribution is not new lattice mathematics itself, but a machine-checked, assumption-audited integration of: (1) typed reverse mapping over heterogeneous carriers, (2) explicit hypothesis tracking for transfer/composition, (3) one-sided adequacy decomposition (sound/complete), and (4) partiality-aware non-adjointness.
All core statements are mechanized in Lean4 and traceable to concrete files.

## 0. Scope and Claim Boundary
This paper is the formal-methods part of a split strategy:
- formal paper: typed semantics + theorem mechanization
- engineering paper: replay pipeline and operational evidence

Target quality bar: FM/ITP/CPP/TACAS/FASE/Formal Aspects.

What this paper claims:
- a self-contained typed model for multi-layer reverse mapping
- explicit assumptions for non-trivial theorems
- machine-checked theorem set with build-reproducible artifacts

What this paper does not claim:
- extractor correctness proofs for concrete regex/LLM extractors
- statistical external validity from small convenience samples
- full temporal/behavioral specification management

## 1. Problem and Goal
Multi-layer artifacts (requirements, API documents, code constraints, etc.) evolve asynchronously.
Local checks can pass while cross-layer comparison semantics remain underspecified.

The central challenge is not "prove a pre-written ideal root spec", because a complete ideal root `U*` is rarely available in practice.
Instead, we construct a root-side comparison basis from partial projections:
- join-side baseline `U0`
- meet-side conjunction `UAnd`

The formal objective is to make this construction assumption-auditable and machine-checkable.

## 2. Typed Model
### 2.1 Core objects
- `Ω`: root space
- `I`: layer index
- `carrier : I -> Type`: heterogeneous layer carriers
- `proj_i : Ω -> Option β_i`: partial projection
- `D(i), A(i) : Set β_i`: domain/admissible sets

Lean core:
- `paper/lean/UadfU0/Definitions/Model.lean`

### 2.2 Induced preimage and lifted sets (must semantics)
For `S ⊆ β_i`:

\[
preimage_i(S) := \{x \in Ω \mid \exists y,\ proj_i(x)=some(y) \land y\in S\}
\]

\[
lifted(i) := preimage_i(A(i))
\]

### 2.3 Two operators on inclusion order
Order is fixed to inclusion `⊆` only.

\[
U0On(active) := \{x \mid \exists i,\ active(i) \land x\in lifted(i)\}
\]
\[
U0 := U0On(\lambda _, True)
\]
\[
UAndOn(active) := \{x \mid \forall i,\ active(i) \to x\in lifted(i)\}
\]
\[
UAnd := UAndOn(\lambda _, True)
\]

Hence, under `⊆`: join = union, meet = intersection.
`U0` is an over-approximate coverage baseline; `UAnd` is conjunctive satisfaction.

### 2.4 Must/may extension
Must is the default above.
May variant admits undefined points:

\[
preimageMay_i(S) := \{x \mid proj_i(x)=none \lor \exists y, proj_i(x)=some(y) \land y\in S\}
\]

This distinction is used for sensitivity analysis, not to mix must and may proofs.

### 2.5 Lean excerpt (core definitions)
```lean
def preimage (M : Model ι α) (i : ι) (S : SpecSet (M.carrier i)) : SpecSet α :=
  fun x => ∃ y : M.carrier i, M.proj i x = some y ∧ y ∈ S

def U0On (M : Model ι α) (active : ι → Prop) : SpecSet α :=
  fun x => ∃ i : ι, active i ∧ x ∈ M.lifted i

def UAndOn (M : Model ι α) (active : ι → Prop) : SpecSet α :=
  fun x => ∀ i : ι, active i → x ∈ M.lifted i
```

## 3. Core Results (Assumption-Explicit)
The main value is explicit hypothesis control. Background lemmas (monotonicity/union/LUB identities) are not front-loaded as novelty.

### 3.1 Transfer theorem (`lifted_transfer`)
Given `R : β_i -> β_j -> Prop`, assume:
- `hproj`: same-root linkage from `proj_j x` to `proj_i x`
- `hA`: admissibility preservation along `R`

Then:
\[
lifted(j) \subseteq lifted(i)
\]

Lean: `paper/lean/UadfU0/InterLayer/Transfer.lean`.

### 3.2 Composition theorem (`preimage_compose`)
Given `g : β_i -> Option β_j` and pointwise equality
\[
proj_j(x) = Option.bind (proj_i(x))\ g
\]
preimages compose through pullback:
\[
preimage_j(S) = preimage_i(pullbackVia_g(S))
\]

Lean: `paper/lean/UadfU0/InterLayer/Composition.lean`.

### 3.3 One-sided adequacy decomposition (`Adequacy.lean`)
For abstract relation `E : Ω -> β_i -> Prop`:
- sound-side inclusion
- complete-side inclusion
- equality when both hold

May side is handled by same-kind comparison with `semanticPullbackMay`.

Interpretation note:
These are abstract theorems over `E`; concrete extractor obligations are separate proof obligations.

### 3.4 Non-adjointness under partiality (`no_left_adjoint_of_partial`)
If `∃x0, proj_i(x0)=none`, induced preimage need not admit a left adjoint.

Lean: `paper/lean/UadfU0/RelatedWork/Galois.lean`.

### 3.5 `U0`/`UAnd` order-theoretic properties
- `U0` as LUB under inclusion
- `UAndOn` as GLB under inclusion
- antitone behavior of `UAndOn` under active-set extension

Lean: `paper/lean/UadfU0/U0Spec/Minimality.lean`, `paper/lean/UadfU0/U0Spec/Construction.lean`.

### 3.6 Ideal root relation with observability domain
To avoid equating `U0` with ideal root `U*`, we track domain-restricted assumptions:
\[
Dom_i := \{x \mid \exists y, proj_i(x)=some(y)\}
\]

Under domain-restricted necessary-condition assumptions, obtain:
\[
U* \cap Dom_{active} \subseteq UAndOn(active) \subseteq U0On(active)
\]
(with non-empty `active`).

Lean: `paper/lean/UadfU0/U0Spec/IdealRoot.lean`.

# Engineering Trust for Multi-Layer Consistency Audits: Deterministic Replay on top of the UAD/f Kernel

## Abstract
This paper presents an engineering trust design for multi-layer consistency audits over requirements/API/code artifacts.
Our core contribution is not formal theorem proving (handled in the companion FM paper), but an operationally reproducible pipeline with explicit uncertainty handling and machine-checkable replay acceptance.
The pipeline fixes inputs by lock+snapshot+hash, separates raw tri-valued judgement from policy projection, and pre-registers mutation expectations.
We report feasibility-stage evidence on three real OSS families plus a deterministic policy-ablation benchmark (21 scenarios) against a strict binary baseline.

## 0. Positioning and Claim Boundary
This manuscript is the engineering paper in a two-paper strategy:
- formal kernel correctness: `paper/formal-methods/manuscript_fm.md`
- engineering replay trust: this paper

Target bar: SE top-conference main-track style (clear pain/goal, reproducible artifact, explicit non-goals, falsifiable evaluation contract).

Non-goals in this paper:
- no statistical population inference from `n=3` convenience sample
- no proof that the concrete regex extractor satisfies formal adequacy hypotheses
- no claim of full behavioral/temporal specification governance

## 1. Pain, Goal, and Stakeholders
### 1.1 Pain
Teams maintain constraints across heterogeneous artifacts.
Frequent failures are:
- silent drift: same intent, different bounds across layers
- extraction fragility: wording drift breaks parsers
- non-replayability: reported results cannot be reconstructed from fixed inputs

### 1.2 Goal
Provide a pipeline where:
1. reported results are replayable from pinned inputs,
2. undefined extraction outcomes are explicit and policy-controlled,
3. contradiction vs uncertainty are separated,
4. mutation expectations are pre-specified and machine-checked.

### 1.3 Users
- quality/reliability engineers who must justify audit outcomes
- platform engineers maintaining multi-layer constraints
- reviewers/auditors who need deterministic replay evidence

## 3. PoC Semantics
### 3.1 Per-layer status
For each layer:
- `supported`: two-sided interval extracted and well-formed (`l <= u`)
- `invalid`: two-sided interval extracted but ill-formed (`l > u`)
- `unknown`: parse failure or one-sided bound only

Important: `invalid` is IR well-formedness failure, not semantic contradiction proof.

### 3.2 Tri-valued judgement and policy projection
- `judgement` (raw): `consistent | contradictory | inconclusive`
- `policy_judgement`: projection of `inconclusive` under policy
  - must: `inconclusive -> contradictory`
  - may: `inconclusive -> consistent`

This avoids conflating logical contradiction with operational uncertainty.

Implementation excerpt (`external_validation.py`):
```python
def apply_none_policy(judgement: Judgement, none_semantics: NoneSemantics) -> Judgement:
    if judgement != "inconclusive":
        return judgement
    return "contradictory" if none_semantics == "must" else "consistent"
```

### 3.3 U0-side indicators vs UAnd-side diagnosis
PoC intentionally separates two observation paths:
- `proj_i^{U0}` path (`interval`) for coverage-style monitoring
- `measure_i^{UAnd}` path (`bounds`) for consistency diagnosis

Operational indicators:
- `u0_support_indicator`
- `u0_unfalsified_indicator`
- `u0_unknown_only`
- `support_ratio`, `unknown_ratio`, `invalid_interval_ratio`

Diagnosis outputs:
- `judgement`
- `policy_judgement`
- intersection bounds when available

- `policy_must`

- contradiction detection rate: must `1.0`, may `1.0`, binary_strict `1.0`

Engineering reading:
- `policy_may` reduces contradiction-side escalation under uncertainty,
- `policy_must` and strict binary aggressively collapse uncertainty to contradiction,
- explicit policy design is materially better than implicit binary collapse.
