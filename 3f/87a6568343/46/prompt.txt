# UAD/f Two-Operator Kernel under Partial Projections: Assumption-Audited Lean4 Mechanization

## Abstract
This paper presents a formal-methods contribution for multi-layer specification comparison under partial projections.
Each layer `i` has its own carrier type `β_i`, and root-to-layer mapping is partial (`proj_i : Ω -> Option β_i`).
On top of this typed kernel we separate two root-side operators with distinct roles:
1. `U0` (join-side coverage baseline)
2. `UAnd` (meet-side conjunctive consistency)

The contribution is an assumption-audited mechanization that makes implicit premises explicit and machine-checkable, with emphasis on failure modes that arise only under partial projections.
We prove, in Lean4, theorems that are technically central in this setting: inter-layer transfer with same-root linkage assumptions, projection composition through `Option.bind` with explicit impossible-branch elimination, one-sided adequacy decomposition (sound/complete split, must/may variants), non-adjointness under partiality, and ideal-root linkage under observability-domain restrictions.
We provide theorem-to-file traceability, explicit proof-obligation interfaces for concrete extractors, and reproducibility metadata.
We do not claim full constructivity for all proofs; axiom usage is disclosed explicitly.

## 1. Problem Statement and Research Questions
### 1.1 Problem
In multi-layer engineering settings, artifacts evolve asynchronously.
Even when each layer passes local checks, cross-layer comparison semantics are often implicit.
The central difficulty is that ideal complete root specification `U*` is usually unavailable in practice, while cross-layer comparison still requires a root-side criterion.

The formal direction taken here is:
1. Do not assume complete `U*` as input.
2. Construct root-side operators from partial projections.
3. Keep every non-trivial theorem explicit about its assumptions.

### 1.2 Formal objective
The objective is to provide a minimal typed kernel where:
1. root-side comparison is constructed from partial projections,
2. join-side and meet-side roles are separated,
3. inter-layer and adequacy theorems are proven with explicit hypotheses,
4. all core statements are machine-checked in Lean.

### 1.3 Research questions
1. `RQ1`: Can we define induced inverse images consistently with heterogeneous carriers `carrier : I -> Type`?
2. `RQ2`: Can `A(i) ⊆ D(i)` be lifted into root-side witness validity guarantees?
3. `RQ3`: Can `U0` (join) and `UAnd` (meet) be defined coherently in one model?
4. `RQ4`: Can transfer/composition conditions be typed and mechanized without hidden assumptions?
5. `RQ5`: Can adequacy be decomposed into one-sided forms (sound/complete) over abstract `E`?

Primary RQs for this formal paper are `RQ3`, `RQ4`, and `RQ5`.
`RQ1` and `RQ2` are supporting questions: they fix typed prerequisites used by the primary theorem families.

### 1.4 Evaluation criteria
1. Definition integrity: type consistency and notation consistency.
2. Theorem integrity: explicit assumptions and machine-checked proofs.
3. Mechanization integrity: no `sorry`, theorem traceability, reproducible build.
4. Claim integrity: clear separation between theorem claims and non-claims.

## 2. Typed Core Model
### 2.1 Notation and order convention
We encode sets as predicates.
- `SpecSet α := α -> Prop`
- this is a local alias in `UadfU0.Definitions.Model`, not a direct use of Mathlib `Set α`
- design choice: this artifact keeps `lake-manifest.json` package list empty (`packages: []`) to expose all assumptions through a minimal Lean-core dependency surface; the tradeoff is reduced immediate reuse of Mathlib-specific interfaces.

Order is fixed to inclusion `⊆` only.
Under this order:
1. join is union,
2. meet is intersection.

This fixed convention prevents semantic drift across sections.

### 2.2 Layer and model structures
Each layer has both domain and admissible predicates.
- `Layer β`:
  - `D : SpecSet β`
  - `A : SpecSet β`
  - `admissible_subset_domain : A ⊆ D`

Typed UAD/f model:
- `Model ι α`:
  - `carrier : ι -> Type`
  - `layer : (i : ι) -> Layer (carrier i)`
  - `proj : (i : ι) -> α -> Option (carrier i)`

This enforces per-layer heterogeneity (`β_i` may differ by index).

Admissible-set alias used in theorem signatures:
- `Ui(i) := A(i)` (compatibility alias)
- in Lean this is `def Ui (M : Model ι α) (i : ι) := M.A i`
- throughout this paper, `Ui` and `A` denote the same predicate at layer `i`

### 2.3 Lean definition excerpt (compilable context)
```lean
namespace UadfU0
namespace Model

variable {ι : Type u} {α : Type v}
variable (M : Model ι α)

def preimage (i : ι) (S : SpecSet (M.carrier i)) : SpecSet α :=
  fun x => ∃ y : M.carrier i, M.proj i x = some y ∧ y ∈ S

def Ui (i : ι) : SpecSet (M.carrier i) :=
  M.A i

def lifted (i : ι) : SpecSet α :=
  M.preimage i (M.Ui i)

def U0On (active : ι → Prop) : SpecSet α :=
  fun x => ∃ i, active i ∧ x ∈ M.lifted i

def UAndOn (active : ι → Prop) : SpecSet α :=
  fun x => ∀ i, active i → x ∈ M.lifted i

def U0 : SpecSet α :=
  fun x => ∃ i, x ∈ M.lifted i

def UAnd : SpecSet α :=
  M.UAndOn (fun _ => True)

end Model
end UadfU0
```
(Pedagogical composite excerpt across `paper/lean/UadfU0/Definitions/Model.lean` and `paper/lean/UadfU0/U0Spec/Construction.lean`; canonical placement is listed in §2.5.)

### 2.4 Induced inverse image and lifted sets (must semantics)
For each layer `i`:

\[
preimage_i(S) := \{x \in Ω \mid \exists y \in β_i,\ proj_i(x)=some(y) \land y \in S\}
\]

Lifted admissible predicate:

\[
lifted(i) := preimage_i(A(i))
\]

### 2.5 Root-side operators
Active-restricted operators:

\[
U0On(active) := \{x \mid \exists i,\ active(i) \land x \in lifted(i)\}
\]
\[
UAndOn(active) := \{x \mid \forall i,\ active(i) \to x \in lifted(i)\}
\]

Global forms:

\[
U0 := U0On(\lambda _, True),\quad UAnd := UAndOn(\lambda _, True)
\]

Interpretation under `⊆`:
1. `U0` is join-side least upper bound.
2. `UAndOn` is meet-side greatest lower bound.

Definition-placement note:
1. `U0` is placed in `Definitions/Model.lean` as core root-side union operator.
2. `UAndOn`/`UAnd` are placed in `U0Spec/Construction.lean` with active-set laws.
3. `U0_eq_U0On_all` and `UAnd_eq_UAndOn_all` provide the explicit bridge for global forms.

### 2.6 May extension
Must excludes undefined projections from membership.
May includes undefined projections as inconclusive-allowed branch:

\[
preimageMay_i(S) := \{x \mid proj_i(x)=none \lor \exists y,\ proj_i(x)=some(y) \land y \in S\}
\]

Derived may operators:
- `liftedMay`
- `UAndMayOn`

Mechanized interface boundary:
1. must and may equalities are proved in separate theorem families (`preimage_eq_semanticPullback` vs `preimageMay_eq_semanticPullbackMay`),
2. cross-family relation is explicit only through named inclusion theorems such as `preimage_subset_preimageMay` and `UAndOn_subset_UAndMayOn`.

### 2.7 Pairwise consistency predicates
\[
Consistent(i,j) :\Leftrightarrow \exists x,\ x\in lifted(i) \land x\in lifted(j)
\]
\[
Contradictory(i,j) :\Leftrightarrow \forall x,\ x\in lifted(i) \to x\in lifted(j) \to False
\]

(Lean: `paper/lean/UadfU0/InterLayer/Consistency.lean`.)

### 2.8 Root-space instantiation templates
We distinguish two conceptual root spaces.
1. `Ω_trace`: event/trace-level root space.
2. `Ω_art`: artifact-bundle root space.

For extractor-aware decomposition:
1. `obs_i : Ω -> Option Γ_i`
2. `extract_i : Γ_i -> Option β_i`
3. `proj_i := Option.bind (obs_i) extract_i`

The formal theorems are stated over abstract `proj_i`; this decomposition is a bridge template, not a hidden assumption.
Concrete instantiation appears in §5.1 (`ArtifactBundleExample.lean`), where `proj` is defined exactly as `Option.bind obs extract`.

### 3.3 Central role-separation result for `RQ3`
From `paper/lean/UadfU0/U0Spec/Construction.lean`:
1. `U0On_monotone`
2. `UAndOn_antitone`
3. `UAndOn_subset_U0On` (requires non-empty active set)
4. `consistent_iff_exists_UAndOn_pair`
5. `UAndOn_empty_eq_univ`

Implication:
1. join-side and meet-side operators are behaviorally distinct,
2. active-layer expansion has opposite monotonicity effects,
3. vacuous-truth edge cases are explicit.

Role-separation theorem bundle (paper-level statement):
1. `U0On` is monotone in active-set growth, while `UAndOn` is antitone.
2. Under non-empty active sets, `UAndOn(active) ⊆ U0On(active)`.
3. Under empty active set, `UAndOn` collapses to universal predicate (`UAndOn_empty_eq_univ`), so any consistency interpretation must explicitly enforce `∃ i, active i`.

Vacuous-truth implication:
1. `UAndOn_empty_eq_univ` means meet over zero active layers yields universal predicate,
2. therefore any operational interpretation of `UAndOn` must enforce non-empty active sets when using it as a consistency signal.
3. the same-root linkage contract used later in `lifted_transfer` (§3.4) is one explicit mechanism for keeping this consistency reading operationally meaningful under partial observations.

Difference from total-map-only intuition:
1. In total-map settings, undefined-observation branch does not exist and must/may collapse.
2. In this partial kernel, strict inclusion can appear (`preimage_subset_preimageMay`, `UAndOn_subset_UAndMayOn`), so join/meet reasoning must be paired with explicit undefined-point policy.
3. Therefore `U0`/`UAnd` separation here is not only order-theoretic; it is policy-sensitive under partiality.

### 3.4 Inter-layer transfer theorem
Formal theorem (`InterLayer/Transfer.lean`):

\[
(\forall x,\forall y_j,\ proj_j(x)=some(y_j) \to \exists y_i,\ proj_i(x)=some(y_i) \land R(y_i,y_j))
\]
\[
\land\ (\forall y_i,y_j,\ R(y_i,y_j) \to y_j\in A(j) \to y_i\in A(i))
\]
\[
\Rightarrow lifted(j) \subseteq lifted(i)
\]

Lean signature excerpt:
```lean
theorem lifted_transfer
    (i j : ι)
    (R : M.carrier i → M.carrier j → Prop)
    (hproj :
      ∀ x : α, ∀ yj : M.carrier j,
        M.proj j x = some yj →
        ∃ yi : M.carrier i, M.proj i x = some yi ∧ R yi yj)
    (hA :
      ∀ yi : M.carrier i, ∀ yj : M.carrier j,
        R yi yj → yj ∈ M.Ui j → yi ∈ M.Ui i)
    : M.lifted j ⊆ M.lifted i
```

Proof skeleton:
1. Take arbitrary `x ∈ lifted(j)`.
2. Extract witness `yj` with `proj_j x = some yj` and `yj ∈ A(j)`.
3. Apply `hproj` at the same root point `x` to get `yi` and `proj_i x = some yi` with `R yi yj`.
4. Apply `hA` to transfer admissibility from `A(j)` to `A(i)`.
5. Construct witness for `x ∈ lifted(i)`.

Assumption audit:
1. Without same-root linkage (`hproj`), codomain relation `R` alone is insufficient.
2. Without admissibility-preservation (`hA`), transfer of set membership fails.
3. Mechanized counterexample without `hproj` is provided in `paper/lean/UadfU0/Examples/TransferCounterexample.lean` (`transfer_fails_without_hproj`), including a case where admissibility-side reasoning is still present (`hA_trivial`).

### 3.5 Composition theorem for induced inverse images
Formal theorem (`InterLayer/Composition.lean`):

\[
proj_j(x)=Option.bind(proj_i(x),g)
\Rightarrow
preimage_j(S)=preimage_i(pullbackVia_g(S))
\]

with

\[
pullbackVia_g(S)=\{y_i\mid \exists y_j,\ g(y_i)=some(y_j)\land y_j\in S\}
\]

Lean signature excerpt:
```lean
theorem preimage_compose
    (i j : ι)
    (g : M.carrier i → Option (M.carrier j))
    (hcomm : ∀ x, M.proj j x = Option.bind (M.proj i x) g)
    (S : SpecSet (M.carrier j))
    : M.preimage j S = M.preimage i (M.pullbackVia g S)
```

Proof skeleton (both directions explicit):
1. `j -> i` direction:
2. Start from witness `yj` in `preimage_j(S)`.
3. Use `hcomm` and case analysis on `proj_i x`.
4. In `none` branch, `Option.bind (proj_i x) g = none`, contradicting `proj_j x = some yj` via `hcomm`.
5. In `some yi` branch, reduce `Option.bind (some yi) g = some yj` to `g yi = some yj` and construct pullback witness.
6. `i -> j` direction:
7. Start from witness `yi` plus pullback witness `yj`.
8. Rebuild `Option.bind` equality and conclude `proj_j x = some yj`.

Why non-trivial in this model:
1. proof depends on partiality-aware branch handling,
2. impossible branch elimination is essential and mechanized.
3. if projections were total (`α -> β`) and `Option` branch were absent, this theorem collapses to standard total preimage-composition identities; here the `none` branch introduces an extra proof obligation that must be discharged explicitly.

### 3.6 One-sided adequacy decomposition (must and may)
From `paper/lean/UadfU0/InterLayer/Adequacy.lean`.

Motivation for introducing abstract `E`:
1. `proj` captures an implementation-level observation path,
2. `E` captures semantic extraction relation used for adequacy statements,
3. separating them allows theorem-level reasoning before committing to a concrete extractor implementation,
4. this separation is required to express mismatched cases (`E ≠ graph(proj)`) where one-sided adequacy still holds and complete adequacy fails.

Definitions:
\[
semanticPullback(E,S):=\{x\mid \exists y, E(x,y)\land y\in S\}
\]
\[
semanticPullbackMay(E,S):=\{x\mid proj_i(x)=none\ \lor\ \exists y, E(x,y)\land y\in S\}
\]

Must-side theorems:
1. `preimage_subset_semanticPullback_of_sound`
2. `semanticPullback_subset_preimage_of_complete`
3. `preimage_eq_semanticPullback`

May-side theorems:
1. `preimageMay_subset_semanticPullbackMay_of_sound`
2. `semanticPullbackMay_subset_preimageMay_of_complete`
3. `preimageMay_eq_semanticPullbackMay`

Interpretation boundary:
1. These are abstract theorems over relation `E`.
2. Extractor-specific correctness is not proven here.
3. Non-triviality under `E ≠ proj` is shown by mechanized counterexample in `paper/lean/UadfU0/Examples/AdequacyCounterexample.lean` (sound side can hold while complete side fails).
4. Concrete `obs/extract` instantiation obligations are mechanized in `paper/lean/UadfU0/Examples/ArtifactBundleExample.lean` (`Eextract_sound`, `Eextract_complete`, `preimage_eq_semanticPullback_Eextract`).

#### 3.6.1 Concrete-extractor proof obligations (template)
For a concrete extractor decomposition:
1. `obs_i : Ω -> Option Γ_i`
2. `extract_i : Γ_i -> Option β_i`
3. `proj_i := Option.bind obs_i extract_i`

typical sufficient obligations are:
1. Sound side:
   - `obs_i x = some γ ∧ extract_i γ = some y -> E_extract x y`
2. Complete side:
   - `E_extract x y -> ∃ γ, obs_i x = some γ ∧ extract_i γ = some y`
3. none-policy side:
   - must or may handling of inconclusive is fixed as an operational policy.

Lean mapping:
1. sound obligation corresponds to `hSound`.
2. complete obligation corresponds to `hComplete`.
3. adequacy application reads as substitution `E := E_extract`.

#### 3.6.2 Why `semanticPullbackMay` contains `proj`-none branch
May-comparison requires matching the same inconclusive policy on both sides.
Therefore `semanticPullbackMay` includes `proj_i(x)=none` branch explicitly.
This is an operational comparability choice, not an arbitrary mixing of abstractions.

### 3.7 Non-adjointness under partial projections
From `paper/lean/UadfU0/RelatedWork/Galois.lean`:

Adjointness notion used:
\[
HasLeftAdjoint(G) :\Leftrightarrow \exists F,\ \forall S,T,\ F(S)\subseteq T \leftrightarrow S\subseteq G(T)
\]
with `G = preimage_i`.

\[
(\exists x_0,\ proj_i(x_0)=none) \Rightarrow \neg HasLeftAdjoint(preimage_i)
\]

Lean signature excerpt:
```lean
theorem no_left_adjoint_of_partial
    (M : Model ι α) (i : ι) (x0 : α)
    (hnone : M.proj i x0 = none)
    : ¬ HasLeftAdjoint (M.preimage i)
```

Proof skeleton:
1. Assume a left adjoint `F` exists.
2. Instantiate adjunction with singleton root set `S = {x0}` and universal codomain set `T = ⊤`.
3. From left side (`F S ⊆ T` trivial), derive right side `S ⊆ preimage_i(T)`.
4. Hence `x0 ∈ preimage_i(T)` and there exists `y` with `proj_i x0 = some y`.
5. Contradiction with `proj_i x0 = none`.

This theorem blocks silent import of total-map Galois intuitions into partial-projection settings.
In this paper the theorem is a mechanized guardrail: any adjunction-based reasoning must explicitly justify totality or equivalent conditions.
It is not claimed as standalone mathematical novelty.

### 3.8 Ideal-root linkage under observability domains
From `paper/lean/UadfU0/U0Spec/IdealRoot.lean`:
1. `UStar : SpecSet α` is an explicit theorem parameter denoting ideal-root predicate
   (it is not constructed by this kernel; theorem statements are parametric in `UStar`)
2. `projDom(i) := {x | ∃ y, proj_i x = some y}`
3. `projDomOn(active) := {x | ∀ i, active i -> x ∈ projDom(i)}`

Representative Lean signature:
```lean
theorem UStar_inter_projDomOn_subset_UAndOn
    {active : ι → Prop}
    (UStar : SpecSet α)
    (hNecessaryOnDom :
      ∀ i : ι, active i →
        (fun x : α => x ∈ UStar ∧ x ∈ M.projDom i) ⊆ M.lifted i) :
    (fun x : α => x ∈ UStar ∧ x ∈ M.projDomOn active) ⊆ M.UAndOn active
```

Key theorems:
1. `UStar_inter_projDomOn_subset_UAndOn`
2. `UStar_inter_projDomOn_subset_U0On_of_nonempty_active`
3. `UStar_subset_UAndMayOn`

Interpretation:
1. under partial observability, ideal-root linkage requires domain-restricted assumptions,
2. may-side linkage and must-side linkage are not interchangeable.
3. because `UStar` is parametric input, these are conditional linkage theorems rather than a construction of `UStar`.

## 4. Mechanization Method and Proof Integrity
### 4.1 Mechanization principles
1. Every theorem states assumptions in argument list.
2. No implicit classical package opening in core files.
3. No empirical evidence is used as theorem proof evidence.

The novelty claim is interface-level and methodological: a single typed partial-projection kernel where assumption boundaries, counterexamples, and theorem families are jointly machine-audited.

Classical overlap (not novelty claims):

Mechanization-specific value in this UAD/f kernel:
1. assumption surfacing:
   - same-root linkage (`hproj`) and admissibility transport (`hA`) are explicit.
2. partiality discipline:
   - `none` branch is first-class and theorem-visible.
3. one-sided adequacy granularity:
   - sound/complete can be reasoned separately before equivalence.
4. adjunction caution:

Per-theorem hardness summary:

2. `preimage_compose` is not immediate under partiality because impossible `none` branches must be eliminated constructively.

### 6.1 Concrete delta against baseline theorem libraries
This subsection states the delta at definition/theorem-interface level.
Primary novelty claim in this section is combination-level: one auditable kernel that simultaneously fixes heterogeneous carriers, partial projections, assumption interfaces, and counterexample-backed boundary theorems.

Baseline capabilities (available in standard theorem-library practice):
1. total-function preimage monotonicity and composition laws (`Set.preimage` / `Set.preimage_comp`-style APIs),
2. lattice-level LUB/GLB facts under inclusion (`sSup`/`sInf` or equivalent order-theory interfaces),
3. generic Galois-connection interfaces for total mappings (`GaloisConnection`-style interfaces).

What this kernel adds as one auditable package:
1. one model combining heterogeneous carriers (`carrier : ι -> Type`) with partial projections (`Option`) and domain/admissibility separation,
2. explicit transfer/composition assumptions as theorem arguments (`hproj`, `hA`, `hcomm`) rather than implicit prose assumptions,
3. adequacy decomposition in both must/may forms with named bridge theorems,
4. explicit non-adjointness boundary theorem under undefined points,
5. assumption matrix and theorem catalog linked to concrete Lean files.

Why not directly reuse only the baseline interfaces:
1. our statements must combine heterogeneously indexed carriers with partial projections in one model signature,
2. transfer/composition/adequacy theorems require explicit hypothesis interfaces (`hproj`, `hA`, `hcomm`, sound/complete sides) tied to that signature,
3. baseline APIs provide component lemmas, but not this full assumption-audited contract bundle (including counterexample-backed failure boundaries) as a single reusable interface,
4. therefore the main delta is a typed theorem interface layer under partiality, not a replacement of general-purpose library lemmas.

Claim boundary for this delta:
1. we do not claim these mathematical identities are new,
2. we claim this specific partial/heterogeneous/assumption-audited kernel is packaged and machine-checked end-to-end.

## 7. Relation to Prior Work
### 7.1 Abstract interpretation and order-theoretic semantics
Abstract interpretation gives language for monotonic abstractions.
This paper contributes a typed partial-projection interface (`Option`-based reverse mapping) where monotonic/order-theoretic statements are tied to explicit assumption arguments and machine-checked failure modes.

### 7.2 Institutions and heterogeneous semantics
Institutional frameworks capture satisfaction transfer across logics.
This paper contributes a narrower but executable kernel: one typed root-operator signature with assumption-audited transfer/composition/adequacy theorems under partial projections.
Definition-level difference: institution-style developments center on signature/sentence/model morphisms and satisfaction transport, while this kernel fixes one root-space predicate semantics and audits partial-observability assumptions (`none` branches, must/may split) directly at theorem-interface level.

### 7.3 View consistency and inconsistency governance
View-consistency literature motivates multi-view comparison problems.
This paper contributes the formal operator layer (`U0`/`UAnd`, transfer assumptions, adequacy interfaces) that can serve as a theorem-audited substrate beneath governance workflows.

### 7.4 BX/synchronization lines
BX and synchronization works treat propagation and consistency restoration.
This paper contributes minimal one-way reverse-mapping contracts (`hproj`, `hA`, `hcomm`) with explicit mechanized counterexamples when contracts are dropped.

### 7.5 Galois-connection mechanization lines
Constructive and mechanized Galois-connection literature motivates careful treatment of adjunction assumptions.
This paper contributes a partiality-specific guardrail theorem (`no_left_adjoint_of_partial`) that blocks unqualified transfer of total-map adjunction intuitions into undefined-point settings.
Definition-level difference: constructive Galois-connection lines typically start from abstraction/concretization interfaces over total maps; our theorem starts from an explicit undefined-point witness (`proj_i x0 = none`) and proves non-adjointness as a boundary condition under partial projection.

### 7.6 Positioning statement
This paper is intended as a mechanized kernel contribution:
1. not a replacement for institution/BX frameworks,
2. not a complete temporal semantics framework,
3. but a reusable formal core with explicit assumptions and machine-checkable proofs.

### 7.7 Definition-level differences from two nearby lines
Difference to institution-style frameworks:
1. this paper does not mechanize general signature/sentence/model morphisms with satisfaction condition preservation,
2. instead it fixes one typed root-kernel with partial projections and proves operator/transfer/adequacy results inside that kernel.
3. tradeoff: we lose full heterogeneous-logic interoperability, but gain a compact theorem interface where every proof obligation is explicit at term level and directly executable in Lean.

Difference to BX/TGG synchronization lines:
1. this paper does not mechanize bidirectional restoration algorithms,
2. instead it proves one-way reverse-mapping conditions (`lifted_transfer`, `preimage_compose`) with explicit hypotheses and failure-mode boundaries under partiality.

Difference to total-map set/order formalizations:
1. undefined projection points are first-class (`Option`) and may alter theorem interfaces (must/may split),
2. `U0`/`UAnd` analysis is coupled with undefined-point policy rather than only total preimage algebra.
3. non-adjointness theorem is used here as a guardrail to prevent accidental reuse of total-map intuitions.

# Assumption Matrix (Core Theorems and Supporting Lemmas)

This appendix summarizes which assumptions each core theorem needs, and what fails if an assumption is removed.

| Theorem or lemma | Required assumptions | Failure mode if removed | Fallback claim | Lean reference |
|---|---|---|---|---|
| `lifted_transfer` | `hproj` (same-root linkage), `hA` (admissibility transport) | Without `hproj`, codomain relation alone cannot lift root witness across layers. Without `hA`, witness does not transfer from `A(j)` to `A(i)`. | No general subset transfer claim; only layer-local lifted predicates remain. | `paper/lean/UadfU0/InterLayer/Transfer.lean` |
| `preimage_compose` | `hcomm : proj_j = bind(proj_i,g)` pointwise | Equality of preimages cannot be derived. Without `hcomm`, the `none` branch cannot be eliminated via bind commutation, so equality reduces to weaker one-sided reasoning only. | Keep separate one-directional implications only when independently proven. | `paper/lean/UadfU0/InterLayer/Composition.lean` |
| `preimage_eq_semanticPullback` | both sound and complete directions for `E` | Only one-sided inclusion is derivable; equality is not justified. | Use `preimage_subset_semanticPullback_of_sound` or `semanticPullback_subset_preimage_of_complete` only. | `paper/lean/UadfU0/InterLayer/Adequacy.lean` |
| `preimageMay_eq_semanticPullbackMay` | may-side sound and complete directions | May-side analogue of must case: equality collapses to one-sided relation only if one direction is missing. | Use `preimageMay_subset_semanticPullbackMay_of_sound` or `semanticPullbackMay_subset_preimageMay_of_complete` only. | `paper/lean/UadfU0/InterLayer/Adequacy.lean` |
| `UAndOn_subset_U0On` | non-empty active set (`∃ i, active i`) | For empty active set, `UAndOn` becomes the universal set (`univ`), so subset to `U0On` is not generally valid. | Restrict to non-empty active sets; for empty active set use `UAndOn_empty_eq_univ` explicitly. | `paper/lean/UadfU0/U0Spec/Construction.lean` |
| `no_left_adjoint_of_partial` | existence of undefined projection point (`proj_i x0 = none`) | Scope note: theorem applies under partiality. For total projections, this theorem makes no non-adjointness claim. | None in general; total case requires separate proof obligations. | `paper/lean/UadfU0/RelatedWork/Galois.lean` |
| `UStar_subset_UAndOn` / `UStar_subset_UAnd` | global necessary-condition premise (`∀ i, active i → UStar ⊆ lifted i`) | If global necessity is unavailable, full-space ideal-root linkage is unjustified. | Use domain-restricted variant over `UStar ∩ projDomOn(active)`. | `paper/lean/UadfU0/U0Spec/IdealRoot.lean` |
| `UStar_inter_projDomOn_subset_UAndOn` | domain-restricted necessary-condition premise | Ideal-root inclusion over full space is not justified under partial observability. | Keep domain-restricted claim over `UStar ∩ projDomOn(active)` only. | `paper/lean/UadfU0/U0Spec/IdealRoot.lean` |

Practical reading rule:
1. if all assumptions hold, use the theorem claim exactly as stated,
2. if any assumption fails or is unproven, fall back to the weaker variant noted in the fallback-claim column (usually one-sided inclusions).
