# Real-Project Engineering PoC (Deterministic Replay)

This directory is the engineering PoC artifact package for replayable multi-layer consistency audit.

It is intentionally scoped as a **feasibility PoC**:
- no population-level inference
- no general NL extractor proof
- no deployment-readiness claim

## 2. Replay Contract
Single entrypoint:
```bash
cd paper/case-study/real_projects
bash reproduce.sh
```

`reproduce.sh` runs 6 sections:
1. offline fail-fast (main lock)
2. graceful must (main lock)
3. graceful may (main lock)
4. drift replay suite (drift lock)
5. edge-case log generation for `classify_uand`
6. policy-ablation benchmark generation

Prechecks (SHA256) are enforced before replay for:
- `external_validation.py`
- `external_validation_sources.lock.json`
- `logs/regex_drift_lock.json`
- `logs/regex_drift_snapshot.txt`

Offline replay mode does not rewrite `external_validation_sources.lock.json`.

## 3. Verification (Python-only, recommended)
```bash
cd paper/case-study/real_projects
bash reproduce.sh
python3 verify_replay.py --logs-dir logs
```

Expected final line:
```text
OK: replay verification checks passed
```

`verify_replay.py` checks:
- 4-field replay acceptance projection
- drift-mode must/may split behavior
- edge-case judgement log structure
- policy-ablation summary metrics

Policy-ablation report generation (already included in `reproduce.sh`):
```bash
python3 evaluate_policy_ablation.py \
  --offline-lock external_validation_sources.lock.json \
  --out-json logs/policy_ablation_report.json \
  --out-md logs/policy_ablation_report.md
```

## 4. Optional jq Checks
```bash
jq '{n_real_projects, raw_judgement_distribution, policy_judgement_distribution, mutation_detected_by_expectation}' logs/external_validation_graceful_may.log
```

`jq` is optional; it is not required for the acceptance path.

## 5. Semantics Used in the PoC
Per-layer status:
- `supported`: two-sided interval extracted and well-formed (`l <= u`)
- `invalid`: two-sided interval extracted and ill-formed (`l > u`)
- `unknown`: parse failure or one-sided bound only

Pipeline:
- `judgement`: raw tri-valued result (`consistent`, `contradictory`, `inconclusive`)
- `policy_judgement`: projection of inconclusive under `must`/`may`

## 6. Acceptance Projection (paper-level)
Deterministic replay pass/fail uses these four fields:
- `n_real_projects`
- `raw_judgement_distribution`
- `policy_judgement_distribution`
- `mutation_detected_by_expectation`

Other fields remain audit detail and are intentionally preserved in logs/results.
