## Summary
The manuscript presents a well-scoped formalization of a multi-layer specification consistency framework (UAD/f model) with Lean4 mechanization. The core separation of U0 (join/coverage baseline) from U∧ (meet/simultaneous-satisfaction) is formally sound and the one-sided adequacy decomposition (RQ5) is a genuine contribution. Non-goal and applicability-boundary disclosures are unusually thorough for a systems paper. However, three blocking issues remain: (1) a definitional ambiguity in the MUS formulation (§3.4) that makes the stated property unprovable as written; (2) an unresolved notational inconsistency between the `UAndOn_antitone` statement in §2.4 and its prose description in §3.3; and (3) the PoC-to-theory interface in §6.2 uses two distinct observation functions (𝑝𝑟𝑜𝑗_𝑖^{U0} vs. 𝑚𝑒𝑎𝑠𝑢𝑟𝑒_𝑖^{U∧}) without formally establishing that they are both instances of the same abstract `proj_i` — this breaks the claim that "the PoC instantiates the UAD/f model." These must be resolved before acceptance.

## Strengths
- The binary-operation separation (U0 = join/OR, U∧ = meet/AND) is formally motivated and avoids the semantic conflation that plagued earlier drafts. The Lean mechanization names are consistently cross-referenced.
- The must/may duality in §4.7 is handled with unusual precision: the direction of false-positive/false-negative errors is correctly derived for both REPORT_CONSISTENT and REPORT_CONTRADICTORY targets, and the Lean theorems `UAndOn_subset_UAndMayOn` and `UAndMayOn_empty_implies_UAndOn_empty` correctly bound the relationship.
- Non-goal declarations and applicability boundary boxes (§0.3, §4.3, §4.8, §6.2) are comprehensive and self-consistent. The separation of RQ5 (abstract E) from RQ6 (deterministic replay) prevents overclaiming.
- The non-adjointness proof (`no_left_adjoint_of_partial`, §4.4) is a non-trivial result that correctly blocks direct import of abstract-interpretation intuitions to partial-projection settings.
- `A(i) ⊆ D(i)` motivation in §2.1 is well-articulated, and the decision to keep D(i) trivial in the PoC while deferring real domain separation is appropriately flagged as a limitation.
- Reproduceability documentation (§7) is rigorous: SHA256 of scripts, offline replay with SHA verification, three-mode reproduce.sh, and jq-free Python-only verification path.

## Required Fixes
- BLOCKING – §3.4 MUS definition is logically incomplete. `MUS(active)` is defined as `Inconsistent(active) ∧ ∀active', active' ⊊ active → ¬Inconsistent(active')`. However, `active' ⊊ active` as defined in the same section uses `∀i, active'(i) → active(i)` (downward subset), which means the minimality quantifies only over *strict subsets* expressed as predicates on ι. In a Lean4 setting where `ι` is an arbitrary type without decidable equality, enumerating all such `active'` is not straightforwardly well-typed, and the definition as given admits the vacuous case where no strict subset exists (e.g., ι a singleton). The manuscript asserts 'MUS抽出アルゴリズムの正当性証明は今後課題' but does not flag that the MUS *definition* itself needs a well-foundedness or finiteness assumption on active to be non-vacuous. Add a explicit side-condition: either `Fintype {i | active i}` or `∃i, active i ∧ ∃active', active' ⊊ active ∧ Inconsistent(active')` as a non-vacuousness guard, and note this in the Lean file reference.
- BLOCKING – §2.4 / §3.3 notational inconsistency in `UAndOn_antitone`. In §2.4 the Lean statement reads: `(hJK : ∀ i, J i → K i) : M.UAndOn K ⊆ M.UAndOn J`. In prose §3.3 the same theorem is described as 'active を増やすと U∧ は反単調に小さくなる'. The Lean statement has conclusion `UAndOn K ⊆ UAndOn J` when `J ⊆ K` (as predicates), meaning *larger* active set → *smaller* UAndOn — this is correct for the inclusion order on SpecSet. However, the prose says 'active を増やすと' (increasing active) gives a *smaller* U∧, which matches. The problem is that the naming convention in §2.4 names the *smaller* predicate `J` and the *larger* `K` (hJK : J ⊆ K), yet the conclusion uses `K` as the argument to the larger UAndOn and `J` as the result. A reader following the Lean statement directly reads 'if J implies K (J is smaller), then UAndOn(K) ⊆ UAndOn(J)' — this is correct but the variable naming `J`/`K` is the reverse of the usual mathematical convention (where the larger set is typically named with the later letter on the left). The inconsistency becomes a real ambiguity at §3.3 bullet '`UAndOn_antitone`: `active` を増やすと `U∧` は反単調に小さくなる（要件が厳しくなる）' — this is consistent with the Lean statement but the direction is implicit. Require: add a one-line explicit statement in §3.3 of the form 'formally: if J(i)→K(i) for all i then UAndOn(K)⊆UAndOn(J)' to make the direction unambiguous without forcing the reader to cross-reference the Lean snippet.
- BLOCKING – §6.2 dual-projection incoherence. The PoC explicitly introduces two separate observation functions: `proj_i^{U0} := interval_hat_i` (both-sided interval, returns none if either bound missing) and `measure_i^{U∧} := bounds_hat_i` (partial bounds, used by classify_uand). The manuscript acknowledges 'PoC は U0 側と U∧側で異なる観測関数を併置する運用構成である' and explicitly disclaims '∀x, classify_uand(bounds_hat(x)) ↔ x ∈ UAndOn の同値主張を行わない'. This is honest. However, the abstract model in §2 defines a *single* `proj_i : Ω → Option β_i` per layer, and both U0 and U∧ are defined using the *same* lifted(i) := preimage_i(A(i)). The PoC therefore does not instantiate the abstract model — it uses a *different* (richer) structure with two observation functions per layer. This gap must be explicitly formalized: either (a) extend the abstract model to allow U0 and U∧ to use different projections (a non-trivial change), or (b) clearly state in a prominently placed remark (not buried in the table footnote) that the PoC is a *two-projection operational approximation* that does not directly instantiate Model in §2, and that the theoretical results of §4 apply only under the assumption that both projections agree — an assumption that is not verified for the concrete regex extractor. As currently written, a reader can reasonably (but incorrectly) infer that the §6.2 PoC serves as a concrete instance of the §2 model.

## Optional Fixes
- §3.5 – The chain 'U* ∩ Dom_active ⊆ U∧_active ⊆ U0On(active)' implicitly requires 'active is nonempty' for the second inclusion (as noted for `UAndOn_subset_U0On`). The condition is mentioned in §3.3 but not restated at the point of the chain in §3.5. Adding '(active nonempty)' as an inline condition would prevent misreading.
- §4.3 – The proof-obligation list for connecting a concrete extractor to the abstract adequacy theorems (items 1–4) is practically valuable but mixes two levels: items 2–3 are Lean-level obligations whereas item 1 (defining E_extract semantically) is a design decision. Consider labeling them as 'Design decision' vs. 'Proof obligation' to help implementors.
- §6.2 table (mutation results) – The zlib `unit_mismatch_upper_scale_down_1024` row shows `mutated_intersection = [-1, 0]` with `expectation_satisfied = true` (criterion: `upper' <= floor(9/1024) = 0`). However `upper' = 0` satisfies `upper' <= 0` only by equality, not strict inequality. This edge case should be noted explicitly to prevent a reader from inferring the test is non-degenerate.
- §7.3 – The claim 'open Classical は導入していない' is a notable design choice that should be accompanied by a brief remark on what it implies: that all results hold in constructive/computational logic. If any theorem implicitly uses classical reasoning via Lean4's kernel (e.g., `Decidable` instances pulled from imported modules), this should be verified and noted.
- General – The manuscript uses both '写像' and '射影' to render 'projection' in Japanese, and 'f_{0i}' vs. 'proj_i' interchangeably throughout. A notation table entry clarifying that 'f_{0i} = proj_i' (same object, two notations) would eliminate a minor but recurrent source of confusion.
