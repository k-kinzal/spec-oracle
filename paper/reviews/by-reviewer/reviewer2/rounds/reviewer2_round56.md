## Required Fixes
- §6.2 mutation table: The column `detection_method` uses two heterogeneous labels — `uand_contradiction` (a U∧ judgement outcome) and `bound_shrinkage` (a numeric criterion on extracted values). The note beneath the table states 'expectation_satisfied=true does not always mean raw_judgement=contradictory', but the table header `detection_method` implies a unified detection mechanism. This asymmetry must be resolved: either rename the column to `detection_criterion_type` with values `{u∧_judgement, bound_metric}`, or add a column `detection_layer ∈ {U∧, U0/metric}` to make clear that the two mutations are assessed by fundamentally different predicates. As written, a reader tabulating 'mutation_detected_by_expectation = 6/6' may conflate the two detection mechanisms and infer a stronger uniform guarantee than the framework provides.
- §4.3 adequacy 運用帰結 block: The four-item list (false consistency, missed consistency, false contradiction, missed contradiction) is repeated almost verbatim in §4.7 under 'adequacy inclusionから得られる誤り方向'. The §4.7 copy lacks the §4.3 warning box ('以下は hSound/hComplete などの抽象仮定が成立する場合の形式的帰結') directly preceding the list. Readers who enter from §4.7 may read the error-direction claims as unconditional properties of the PoC pipeline. Add the same conditioning note at the head of the §4.7 reprise, or replace the reprise with a cross-reference to §4.3.
- §7.5 truncated sentence: The final sentence ends mid-word ('オフライン追試で SHA256 不一致が…'). This is an editorial incompleteness that must be resolved before publication; a truncated sentence in the reproducibility section creates direct doubt about whether the verification procedure is fully specified.

## Optional Fixes
- §3.1 運用ミニシナリオ note: 'ただし原因層の最小化（MUS/unsat core 抽出）は本稿の証明範囲外' — this parenthetical is accurate but appears immediately after the PoC change-propagation scenario, which may cause readers to wonder whether §3.4's MUS definition is therefore vacuous. Consider adding one sentence clarifying that §3.4 provides the formal problem statement (necessary for future algorithmic work) even though the algorithm itself is deferred.
- §6.3 'code.lower が null となる' interpretation: The manuscript correctly states this 'primarily reflects the extractor's limit' rather than claiming the API has no lower bound. However, the word 'primarily' (主に) introduces residual ambiguity. Replacing with 'reflects the regex extractor's inability to locate a lower-bound pattern in the sampled artifact' would be more precise and eliminate the hedging.
- §2.7 IR minimum schema: The `evidence_span.source` field is typed as `URL`. In a formal model section this is slightly inconsistent with the otherwise type-theoretic style. Annotating it as `String` (or `URI`) would maintain schema-internal type consistency.
- §6.2 'U0_unfalsified は unknown を含むため真になりやすく、単独評価には不向き' — this caveat is accurate but appears after the metric is already listed in the summary table. Consider moving this caveat to the point where `U0_unfalsified` is first defined (the definitional paragraph) rather than deferring it to §6.3, to prevent readers from treating the metric as primary during their first pass through §6.2.
- §4.4 non-adjointness theorem: The current statement 'preimage_i は冪集合上の左随伴を持たない' is correct but could benefit from one sentence noting the practical implication: specifically, that over-approximation monotonicity (§4.6 preimage_monotone) is preserved, but the stronger Galois-connection closure properties are not — so U0 is a valid join but not a residuation closure.
