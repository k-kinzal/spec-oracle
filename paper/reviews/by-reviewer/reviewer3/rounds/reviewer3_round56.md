## Summary
The core deterministic replay pipeline (RQ6) is structurally sound and internally self-consistent: the lock file SHA256 values, snapshot references, extraction patterns, and log outputs all agree with each other. The script logic correctly implements the documented three-value judgement pipeline and mutation detection. However, two blockers prevent an independent third party from performing a clean replay solely from the manuscript: (1) the `external_validation.py` SHA256 documented in §7.2 (`970c0fcc...`) cannot be verified against the current file without executing a hash—the file in the repo may have changed since the 2026-02-17 reference date, and the manuscript provides no tooling to surface this mismatch before replay; (2) the SQLite source URL contains a URL fragment (`#pragma_page_size`) that is collapsed by `slugify()` and stored as a snapshot path, but the fragment is not fetched by `urllib.request.urlopen` (fragments are client-side only), meaning the downloaded content is actually the full `pragma.html` page, not a fragment-anchored subsection—this is undocumented and the lock SHA256 reflects the full page, not the claimed fragment. The manuscript §6.4 references three drift logs (`regex_drift_failure.log`, `regex_drift_graceful_must.log`, `regex_drift_graceful_may.log`) and a `regex_drift_lock.json` as committed artifacts, but these are not present in the provided file set, making §6.4 unreproducible from the supplied package. The `reproduce.sh` does not cover drift-failure scenarios. The `avg_support_ratio` and `avg_unknown_ratio` figures in the log (`0.777...`, `0.222...`) match the manuscript's rounded values (`0.778`, `0.222`), confirming numerical consistency. All 6 mutation expectations are satisfied and internally consistent with the script logic.

## Required Fixes
- BLOCKER — Script hash unverifiable at replay time: §7.2 documents external_validation.py SHA256 as `970c0fcc6d7407362a5b1a31fd0f9526a7cd05d8bbd0944032e054565dc8206b` (2026-02-17 run). The reproduce.sh does not verify the script's own hash before execution, so a reviewer cannot detect hash drift without manual intervention. Add a self-verification step in reproduce.sh (e.g., `sha256sum external_validation.py` compared to the documented value) so that hash mismatch surfaces immediately on replay.
- BLOCKER — §6.4 drift-failure log artifacts are referenced as committed evidence (`regex_drift_failure.log`, `regex_drift_graceful_must.log`, `regex_drift_graceful_may.log`, `regex_drift_lock.json`) but are absent from the provided file set. The manuscript states 'saved' and 'compared' but these files are not in the reproduction package. Either include these files or remove §6.4's claim that they are verifiable committed artifacts.
- BLOCKER — SQLite URL fragment semantics are undocumented: the lock records `https://www.sqlite.org/pragma.html#pragma_page_size` but `urllib.request.urlopen` silently ignores the fragment and fetches the full `pragma.html`. The snapshot therefore contains the entire pragma page, not a fragment-anchored subsection. This must be documented explicitly (e.g., as a note in the lock file and §7.5) so reviewers understand that the SHA256 covers the full page and that fragment-anchored extraction relies on text-search rather than structural navigation.

Harmonize or explain the date discrepancy (lock date vs. retrieval date vs. manuscript run date) to avoid reviewer confusion.
